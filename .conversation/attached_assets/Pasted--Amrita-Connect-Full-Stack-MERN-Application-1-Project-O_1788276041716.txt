# Amrita Connect — Full-Stack MERN Application

## 1. Project Overview

Build a **production-ready full-stack MERN web application** called **Amrita Connect**.

### Tagline

**"One University. Every Campus. One Connected Community."**

Amrita Connect is a professional university networking and collaboration platform connecting:

* Students
* Seniors
* Alumni
* Faculty
* Researchers
* Staff

across all Amrita campuses.

The platform should help users discover:

* The right person
* The right mentor
* The right teammate
* The right research collaborator
* The right opportunity

### Product Positioning

This is **not a social-media application**.

It should feel like a combination of:

* LinkedIn
* GitHub Community
* University Network
* Mentorship Platform

built specifically for the Amrita ecosystem.

# 6. Authentication Module

Create:

* Landing Page
* Registration Page
* Login Page
* Logout functionality

## Registration Fields

* Full Name
* Email
* Password
* Role
* Campus
* Department
* Graduation Year

Additional profile information can be completed after registration.

## Authentication Flow

1. User registers.
2. Password is hashed using bcrypt.
3. User account is stored in MongoDB.
4. User logs in.
5. Backend generates JWT.
6. Frontend stores authentication state securely.
7. Protected routes require authentication.
8. User is redirected to the appropriate dashboard based on role.

Implement authentication middleware on protected APIs.

# 28. Important Implementation Rules

1. **Do not build everything in one step.**
2. First create the project structure and verify that frontend, backend and MongoDB connection work.
3. Implement features incrementally.
4. After each major module, verify that the application still runs.
5. Do not leave placeholder buttons for core functionality.
6. Do not hardcode user data for production features.
7. Use MongoDB for persistent data.
8. Use reusable React components.
9. Keep controllers, routes, models and services separated.
10. Use environment variables for secrets.
11. Implement proper loading, error and empty states.
12. Maintain a consistent deep-blue, white and gold professional design.
13. Keep the UI academic/professional rather than social-media-like.
14. Ensure all protected APIs verify JWT authentication.
15. Ensure role-specific APIs verify authorization.
16. Use REST APIs between frontend and backend.
17. Use Socket.io only for real-time communication.
18. Keep the application responsive.
19. Do not introduce unnecessary libraries.
20. Before finishing, verify that the complete application can be installed and started from a clean environment.
